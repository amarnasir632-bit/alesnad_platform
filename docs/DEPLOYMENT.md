# خطة نشر منصة الإسناد الأكاديمي

## تجربة مجانية قبل شراء الخادم

للتجربة فقط، يستخدم المشروع خدمة Render من نوع Web Service عبر Docker، وتستضيف PHP الواجهة والـAPI معًا. قاعدة البيانات PostgreSQL تكون على Neon. المشروع ليس واجهة JavaScript منفصلة حتى يُنشر كـStatic Site. خطوات الإعداد وحدود الخطة موضحة في [دليل Render وNeon](FREE_HOSTING_RENDER_NEON.md).

هذه بيئة إثبات تشغيل وليست إطلاقًا عامًا أو إنتاجًا: خدمة Render المجانية تتوقف بعد الخمول، ونظام الملفات فيها مؤقت، لذلك لا تحفظ ملفات الطلاب أو محتوى تريد الاحتفاظ به عليها. اختبر بمعلومات تجريبية فقط، وخذ في الاعتبار حدود نقل البيانات والحوسبة في Neon. لا تستخدم نطاقًا عامًا أو بيانات طلاب حقيقية في هذه المرحلة.

## المعمارية المستهدفة بعد موافقة الشركة

- التطبيق: PHP 8.4+، وweb root على `public/` فقط.
- قاعدة البيانات: PostgreSQL، على الخادم نفسه أولًا أو منفصلة لاحقًا.
- DNS وحماية الموقع: Cloudflare.
- الحصص المباشرة والتسجيلات: Cloudflare Stream؛ يتطلب الاختبار مفاتيح حساب حقيقية.
- النسخ الاحتياطي: وجهة خارجية مستقلة مع اختبار استعادة موثق.

إعداد Render المجاني لا يحقق النسخ الاحتياطي ولا تخزين الملفات الدائم ولا جدولة المهام. تبقى هذه متطلبات عند تجهيز خادم الشركة.

## تجهيز الخادم الإنتاجي لاحقًا

1. إعداد نظام مدعوم مع PHP 8.4+ و`pdo_pgsql` و`fileinfo` و`mbstring` وPostgreSQL وخادم ويب.
2. ضبط web root على `public/` ومنع تقديم `.env` و`database/` و`app/` و`storage/`.
3. تثبيت TLS وضبط Cloudflare على Full (strict)، وتعطيل التخزين المؤقت لصفحات الجلسات والمحتوى الخاص.
4. إنشاء مستخدم محدود للتطبيق وفصل صلاحيات تعديل المخطط عن مستخدم التشغيل إذا أمكن.
5. إعداد الأسرار خارج Git، وتعيين `APP_ENV=production` و`APP_DEBUG=0` و`APP_URL` و`SESSION_SECURE=1` والاتصال الآمن بقاعدة البيانات.
6. تشغيل `php database/migrate.php` بإجراء نشر مضبوط. ترحيلات المخطط الحالية تصل إلى `011_quiz_manager_approval_and_retry.sql`؛ يتحقق المشغل من checksums ويستخدم advisory lock.
7. إنشاء حساب المدير الأول من طرفية آمنة، دون كلمة مرور افتراضية.
8. إعداد التخزين الخاص خارج web root، وضبط حدود PHP للرفع بما يوافق `UPLOAD_MAX_BYTES`.
9. إعداد نسخة احتياطية مشفرة ومجدولة خارج الخادم وتجربة استعادة على قاعدة منفصلة.
10. جدولة `php database/process_expired_quiz_attempts.php` كل دقيقة. في Render المجاني لا توجد جدولة دورية مضمونة؛ الطلبات تصنف المحاولات المنتهية عند التفاعل، وهذا كافٍ للعرض التجريبي فقط.
11. اختبار الصلاحيات وCSRF والرفع الخاص والدعوات والبث والنسخ والاستعادة على بيئة ما قبل الإنتاج قبل فتح الموقع للطلاب.

## متطلبات ما قبل الإطلاق العام

- اختبار متكامل لكل متطلبات SRS والواجهات والأدوار على نسخة ما قبل الإنتاج.
- إدخال المراحل والصفوف والمواد يدويًا وفق منهج وزارة التربية والتعليم السودانية.
- اختبار التسجيل الذاتي ومنح الوصول للمحتوى يدويًا من المدير أو المراجع.
- اعتماد سياسات الخصوصية والاستخدام وإقرار المستخدمين بها.
- اعتماد حدود الاستضافة، استخدام الفيديو، الاحتفاظ بالرسائل، وRPO/RTO.
- إعداد Cloudflare Stream واختبار بث مباشر وتسجيل ومشاهدة بصلاحيات صحيحة.
- تشغيل واختبار النسخ الاحتياطية والاستعادة.
