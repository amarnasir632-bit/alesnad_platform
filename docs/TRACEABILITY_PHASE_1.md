# مصفوفة تتبع المرحلة الأولى

توصل هذه المصفوفة متطلبات المرحلة الأولى في SRS بمكونات التنفيذ واختبارات القبول. «موجود» يعني أن الملف/الاختبار أضيف؛ ولا يعني أن تشغيل الاختبار نجح في بيئة لا تتوفر فيها PHP وPostgreSQL.

| متطلب SRS | التغطية في التنفيذ | الاختبار | الحالة |
| --- | --- | --- | --- |
| FR-001 إدارة الحسابات | `AccountService.php` و`AccountController.php`: إنشاء وتعديل وتعطيل، ملف موظف للأستاذ/مراجع المحتوى؛ التسجيل الذاتي يحفظ الصف النشط المختار | `tests/phase1_integration.php`: إنشاء حساب الطالب والتحقق من صفه، تحديث الحساب وتعطيله ورفض تعطيل آخر مدير | أضيف؛ يتطلب تشغيلًا على PostgreSQL |
| FR-002 تسجيل الدخول | `auth.php` و`login_throttle.php`: التحقق، قفل المحاولات، تدوير الجلسة، التدقيق | اختبار نجاح/فشل وتجاوز حد المحاولات في `tests/phase1_integration.php` | أضيف؛ يتطلب إعداد إعدادات الاختبار |
| FR-003 الأدوار والصلاحيات | `authorization.php`: إعادة تحميل المستخدم والأدوار لكل طلب، واستعلام `role_permissions` | اختبار صلاحية صحيحة وتغيير دور ثم التحقق بالطلب التالي | أضيف؛ يتطلب تشغيلًا على PostgreSQL |
| FR-030 السجلات والمراقبة | `audit.php`: دخول نجاح/فشل، تسجيل، خروج، إنشاء/تعديل الحساب وتغيير الدور | تحقق سجلات الأحداث المرتبطة بعمليات الاختبار | أضيف للأحداث المتاحة في المرحلة |
| NFR-001 الأمان والخصوصية | CSRF، PDO، تجزئة موحدة، حد 72 بايت، جلسة خاملة، HSTS بالإنتاج، منع آخر مدير | اختبارات كلمة المرور وCSRF والجلسة والصلاحيات في اختبارات المرحلة | أضيف؛ يلزم تنفيذ PHP محليًا للتحقق |
| NFR-002 التحكم بالوصول | `require_permission`, `require_role` ورفض 403 من API، إعادة التحقق من حالة المستخدم | اختبارات رفض بلا صلاحية وبعد تعطيل الحساب/تغيير الدور | أضيف؛ يتطلب تشغيلًا على PostgreSQL |

## اختبارات التحقق

يسرد `GET /api/v1/admin/roles` الأدوار المسموح بها لحساب مخول بـ`roles.manage`.

- `tests/password_policy.php`: اختبار مستقل لسياسة كلمة المرور باستخدام PHP CLI.
- `tests/phase1_integration.php`: تكامل على قاعدة PostgreSQL مخصصة اسمها يبدأ بـ`alesnad_test_`. يتطلب تطبيق الترحيلات، وإعداد متغيرات الاختبار، ولا يعمل على قاعدة تشغيل عامة.
- قبل الدمج، شغّل `php tests/password_policy.php` و`php tests/phase1_integration.php` ثم `php -l` على ملفات PHP الجديدة والمعدلة. أرفق النتائج الفعلية في مراجعة PR؛ لا تعتبر الاختبارات ناجحة قبل تشغيلها.

## نتائج التحقق المسجلة

- فحص ساكن للمستودع: 16/16 ناجحًا، بما فيها ربط تسجيل الطالب بصف نشط.
- `php -l` لكل ملفات PHP: ناجح.
- `php tests/password_policy.php`: 6/6 ناجحة.
- اختبار API عبر CLI: إصدار CSRF أعاد 200 JSON، ومسار الحسابات دون صلاحية أعاد 403، وطلب logout دون CSRF أعاد 419.
- ترحيلات PostgreSQL 001–004 على قاعدة مؤقتة: نجحت، ووجدت 4 أدوار و18 صلاحية وجدول محاولات الدخول.
- استعلام تحديد المحاولات الفعلي في PostgreSQL: المحاولة الأولى دون قفل، والثانية عند حد الاختبار فعّلت القفل.
- `tests/phase1_integration.php` لم يُشغّل لعدم توفر PostgreSQL مستجيب في بيئة التنفيذ؛ امتداد PHP `pdo_pgsql` متاح.

أي أحداث مراجعة أو نشر أو تنزيل ستضاف في مراحلها الوظيفية اللاحقة مع اختبار تدقيق لكل عملية؛ لا تدعي هذه المرحلة وجود تلك الوظائف.
