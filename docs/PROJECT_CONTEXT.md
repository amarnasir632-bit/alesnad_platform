# سياق منصة الإسناد الأكاديمي

هذا الملف مرجع أساسي للمطورين ومساعدات الذكاء الاصطناعي. اقرأه قبل تعديل النظام. يميز بين ما قرره مالك المشروع، وما صُمم في قاعدة البيانات، وما نُفذ في التطبيق، وما بقي ضمن خطة التطوير. لا تعتبر المتطلب منفذًا لمجرد وروده في BRD أو SRS.

## 1. تعريف المنتج والجهة

- **الاسم التجاري:** منصة الإسناد الأكاديمي.
- **الجهة المشرفة والمنفذة:** AL WARITH (الوارث).
- **الشعار:** `public/assets/brand/al-warith-logo.jpg`.
- **السوق والمنهج:** السودان والمنهج السوداني.
- **نوع المنتج:** منصة ويب تعليمية عربية تجمع المواد والدروس والموارد والاختبارات والحصص والرسائل والاشتراكات.
- **المستخدمون:** الطالب، الأستاذ، مدير النظام/الأدمن، ومراجع المحتوى. ولي الأمر خارج النطاق الأولي ما لم يعتمد لاحقًا.
- **القيمة:** توفير وصول منظم للمحتوى والتقييم والتواصل، مع واجهة عربية RTL واهتمام بالهاتف والاتصال المحدود.

## 2. مصدر الحقيقة

1. آخر قرار صريح من مالك المشروع يحسم المتطلبات والقرارات التجارية.
2. BRD وSRS الإصداران 1.0 يصفان النطاق المقترح، وهما مسودتان تتطلبان اعتماد القرارات المفتوحة.
3. ترحيلات SQL والشيفرة الفعلية تحددان ما أُعد أو نُفذ تقنيًا.
4. `SqlDigram/` مرجع بصري أولي؛ المخطط التنفيذي في `database/migrations/` هو مصدر بنية PostgreSQL.
5. لا تخلط بين «مخطط له» و«منفذ» أو بين قرار مالك المشروع والقرار الفني الذي ما زال بانتظار التنفيذ.

## 3. التقنية والمعمارية المعتمدتان

- **Frontend:** HTML5 وCSS3 وJavaScript ES6+.
- **Backend:** PHP 8.4 أو أحدث متوافق.
- **Database:** PostgreSQL.
- **اتصال قاعدة البيانات:** PDO باستخدام `pdo_pgsql` واستعلامات محضرة.
- **الواجهة:** قوالب PHP وخدمات الخادم، عربية RTL ومتجاوبة.
- **تبادل البيانات:** JSON عند بناء API؛ صفحات الويب الحالية خادمية.
- **الإطار:** لا يفرض BRD/SRS إطار PHP بعينه؛ التنفيذ الحالي PHP أصلي دون إطار.
- **الوقت المحلي:** `Africa/Khartoum`، وتخزن الأوقات في PostgreSQL مع المنطقة الزمنية.

احفظ كلمات المرور عبر `password_hash()` وتحقق منها بـ`password_verify()`. لا تخزن كلمات المرور أو تفاصيل بطاقات الدفع بنص واضح. الأسرار وإعدادات الاتصال في `.env` غير المتعقب في Git. التحقق من الهوية والصلاحية يجب أن يتم على الخادم، وليس في JavaScript وحده.

## 5. نطاق المنتج

### المرحلة الأولى المستهدفة

- حسابات وتسجيل دخول وأدوار وصلاحيات للطالب والأستاذ ومدير النظام ومراجع المحتوى.
- إدارة المراحل والصفوف والمواد والدروس والتصنيفات.
- مكتبة موارد وكتب قابلة للبحث والتنزيل حسب الاشتراك والصلاحيات وحقوق النشر.
- رفع الأستاذ للمحتوى ومراجعته من الأدمن قبل النشر.
- بنك أسئلة مصنف حسب المادة والدرس والنوع والصعوبة.
- أرشيف امتحانات سابقة.
- اختبارات إلكترونية أساسية، تصحيح تلقائي للأسئلة الموضوعية، ونتائج للطالب والأستاذ المخول.
- جدولة الحصص، ربط مزود بث، وإتاحة التسجيلات بعد انتهاء الحصة حسب الصلاحية.
- رسائل فردية بين الطالب والأستاذ.
- اشتراك شهري. الدفع الإلكتروني يعتمد على مزود يختار لاحقًا.
- لوحة إدارة للحسابات والمواد والمحتوى والأسئلة والامتحانات والاشتراكات.
- واجهة عربية RTL، متجاوبة، ومراعية لتقليل استهلاك البيانات.

### لاحق أو مشروط

توليد الأسئلة بالذكاء الاصطناعي، الألعاب التعليمية، بوابة ولي الأمر، تطبيق جوال مستقل، التقارير المتقدمة، الشهادات، الإشعارات الموسعة، وإضافات المراحل. كل ميزة تحتاج اعتماد نطاق وتكلفة قبل بدء تنفيذها.

### خارج النطاق ما لم يعتمد لاحقًا

إنتاج جميع الكتب والفيديوهات من الصفر، العمل الكامل دون اتصال، سعة أو سرعة غير محدودة، التصحيح الآلي الكامل للمقالي، والدفع قبل تحديد مزود الخدمة ومتطلباته.

## 6. قاعدة البيانات

### الترحيلات

- `database/migrations/001_initial_schema.sql`: ينشئ مخطط PostgreSQL والجداول والعلاقات والقيود والفهارس.
- `database/migrations/002_seed_access_control.sql`: يضيف أدوار الطالب والأستاذ ومراجع المحتوى ومدير النظام، والصلاحيات وربطها بالأدوار.
- `database/migrations/003_seed_initial_academic_structure.sql`: يضيف المراحل الابتدائية والمتوسطة والثانوية والصف السادس والثالث الثانوي، وفق نطاق الإطلاق المبدئي.
- `database/migrations/004_auth_security.sql`: يضيف جدول محاولات الدخول المقيدة؛ لا يغير الترحيلات 001–003.
- `database/migrate.php`: ينفذ ملفات الترحيل مرتبة مرة واحدة، ويسجلها في `schema_migrations` داخل معاملة.
- لكل تغيير لاحق، أنشئ ملف ترحيل جديدًا برقم متزايد. لا تعدل ملف ترحيل طُبق على بيئة مشتركة.

الجداول تستخدم مفاتيح أجنبية وقيود تحقق وفهارس على مفاتيح البحث والربط. يستخدم سجل مراجعة المحتوى هدفًا واحدًا من المورد أو الامتحان أو السؤال؛ ويمنع القيد تسجيل هدفين في المراجعة ذاتها. الملفات تخزن بمفتاح تخزين خاص لا بمسار عام. ملفات الفيديو يمكن أن ترتبط بنسخ متعددة في `resource_variants`، وتخزن أحجامها بالبايت وبيانات الدقة ومعدل البت عند توفرها.

### بيانات أولية وقرارات البيانات

الترحيلات تزرع الأدوار والصلاحيات والمراحل والصفين المحددين فقط. لا تزرع موادًا أو مناهج تفصيلية أو أسعار اشتراك أو عملة؛ أدخلها بعد اعتماد العميل. لا توجد بيانات طلاب حقيقية ضمن المستودع. لا ترفع PostgreSQL dump أو قاعدة محلية إلى GitHub.

## 7. تنفيذ التطبيق الحالي

### جاهز في المستودع

- `app/Support/env.php`: تحميل إعدادات `.env` دون اعتماد خارجي.
- `app/Database/connection.php`: PDO PostgreSQL مع الاستعلامات الأصلية المحضرة ووضع أخطاء الاستثناء.
- `app/Auth/auth.php`: تسجيل طالب مع معاملة تشمل المستخدم والدور وملف الطالب؛ تسجيل الدخول، تجزئة/التحقق من كلمة المرور، تحديد المحاولات، التدقيق، تدوير الجلسة والخروج.
- `app/Security/authorization.php`: إعادة التحقق من الحساب النشط والأدوار لكل طلب، وفحص الصلاحيات من `role_permissions` ورفض API 403.
- `app/Security/audit.php`: `audit_log()` لكتابة الأحداث في `audit_events`.
- `app/Security/login_throttle.php`: قفل محاولات الدخول بإعدادات مطلوبة من `.env` وبصمة HMAC للبريد.
- `app/Services/AccountService.php`: إنشاء وتعديل وتعطيل الحسابات وتعيين الأدوار ومنع تعطيل آخر مدير نشط.
- `app/Services/AcademicService.php` و`app/Http/Controllers/AcademicController.php`: إدارة المراحل والصفوف والمواد وروابطها والدروس وإسناد الأساتذة، وتصفية الموارد حسب التصنيفات.
- `app/Http/Router.php` و`app/Http/Controllers/`: موجّه API ومتحكمات المصادقة والحسابات.
- `docs/OPEN_DECISIONS.md`: سجل القرارات المعلقة وقيم إعداد الأمان التي لا يجوز تخمينها.
- `app/Database/catalog.php`: قراءة المواد والصفوف والمراحل والدروس المنشورة للاستعراض.
- `app/Views/`: تخطيط عربي RTL وصفحات البداية والمواد والتسجيل والدخول.
- `public/index.php` و`public/router.php`: نقطة الدخول وموجّه خادم التطوير للـ API والويب مع تمرير الملفات الثابتة مباشرة.
- `public/assets/`: CSS وJavaScript والصور والخطوط العامة، مع شعار AL WARITH.
- `storage/private/` و`storage/backups/`: مساحات خارج web root للملفات الخاصة والنسخ؛ لا يوجد بعد رفع ملفات أو تدفق نسخ احتياطي.
- `database/create_admin.php`: ينشئ حساب مدير أول من الطرفية التفاعلية دون كلمة مرور افتراضية.

### أضيف في المرحلة الثانية

- API لإدارة المراحل والصفوف والمواد وربطها والدروس، وتفعيل السجلات أو تعطيلها دون حذف بيانات مترابطة.
- إسناد الأستاذ النشط ذي دور `teacher` إلى ربط صف ومادة، وإتاحة قائمة إسنادات الأستاذ الحالي.
- بحث API بالمرحلة والصف والمادة والدرس والنص ضمن الموارد المعتمدة؛ لا يعيد مفاتيح التخزين أو روابط الملفات.
- الترحيل `005_academic_management.sql` يضيف صلاحية `teaching_assignments.manage` إلى المدير فقط. المرحلة المتوسطة بلا صفوف مزروعة؛ يدخل المدير الصفوف بعد اعتماد أسمائها (OD-19).
- لم تُعدل الترحيلات 001–004. لم تُعدل `app/Views/` أو `public/assets/`؛ عقد API موثق في `docs/API_CONTRACT.md` ومصفوفة التتبع في `docs/TRACEABILITY_PHASE_2.md`.

### لم يُنفذ بعد

رفع الملفات وتنزيلها، سير اعتماد المحتوى، تطبيق استحقاقات الاشتراك، ربط البث والتخزين، بنك الأسئلة والاختبارات، الرسائل، ومهمة النسخ الاحتياطي والاستعادة. سجل التدقيق موصول بأحداث الهيكل الدراسي والإسناد، إضافة إلى المصادقة والتسجيل وإدارة الحسابات والأدوار؛ توصل أحداث المراجعة والنشر والتنزيل عند تنفيذ نقاطها الوظيفية. وجود الجداول وحده لا يعني اكتمال الوظيفة.

واجهة إنشاء الحساب العامة تنشئ دور الطالب فقط. لا توجد صفحة عامة تسمح باختيار دور أستاذ أو مدير. لا تنشئ حساب مدير افتراضيًا أو بكلمة مرور ثابتة.

نقاط API الحالية تشمل الجلسة والمصادقة وإدارة الحسابات والهيكل الدراسي والبحث. تفاصيلها في `docs/API_CONTRACT.md`، والتغطية والاختبارات في `docs/TRACEABILITY_PHASE_1.md` و`docs/TRACEABILITY_PHASE_2.md`.

## 8. تشغيل المطور

المتطلبات: PHP 8.4+ مع `pdo_pgsql`، PostgreSQL وعميل `psql`، وGit. خطوات إنشاء قاعدة محلية وتشغيلها في `README.md`:

1. إنشاء دور وقاعدة محليين في PostgreSQL.
2. نسخ `.env.example` إلى `.env` وإدخال كلمة مرور محلية وقيم الأمان المعتمدة؛ القيم الإلزامية بلا افتراضات في المثال.
3. تشغيل `php database/migrate.php`.
4. تشغيل `php database/create_admin.php` من طرفية تفاعلية لإنشاء المدير الأول.
5. تشغيل خادم PHP على `public/`.

يستخدم كل مطور قاعدة محلية مستقلة، بينما يشترك الفريق في ملفات ترحيل SQL. لا تشاركوا `.env` أو قاعدة بيانات مطورة بين أعضاء الفريق.

## 9. الأمن والخصوصية

- استخدم أقل صلاحية لازمة لمستخدم PostgreSQL، ولا تستخدم حساب `postgres` من التطبيق.
- استخدم PDO والمعاملات عند حفظ العمليات المرتبطة، واهرب المخرجات عبر `htmlspecialchars`.
- نماذج POST تستخدم CSRF. يجب أن تستمر حماية CSRF وفحص الصلاحية في أي نموذج أو endpoint جديد.
- API يتطلب CSRF لكل طلب مغير، ويعيد تحميل حالة الحساب والأدوار من PostgreSQL في كل طلب.
- كلمات المرور مجزأة عبر PHP. لا تسجل كلمات المرور أو رموز الجلسات أو بيانات الدفع.
- السياسة الموحدة الحالية: 12 محرفًا على الأقل و72 بايت كحد أقصى. إعدادات مهلة الجلسة ومحاولات الدخول إلزامية بلا قيم افتراضية حتى يعتمدها مالك البيئة.
- يرسل التطبيق HSTS في الإنتاج (`APP_ENV=production`)؛ فعّل `SESSION_SECURE=1` خلف HTTPS.
- التطبيق يحتاج HTTPS في الإنتاج، و`SESSION_SECURE=1`، وحدود جلسات مناسبة.
- لا تخدم الملفات الخاصة من `public/`. نفذ endpoint تنزيل يتحقق من هوية المستخدم وصلاحية الاشتراك وحقوق الملف قبل إرساله.
- بيانات الطلاب قد تخص قُصّرًا؛ يجب تحديد الموافقات والاحتفاظ والحذف والإجراءات النظامية قبل الإطلاق.
- قيم ملف النسخ الاحتياطي بيانات وصفية فقط؛ التخزين المجدول والتشفير والاستعادة لم تنفذ.
- لا تستخدم بيانات تجريبية أو شخصية حقيقية في مستودع Git.

## 10. قرارات لا تزال مطلوبة

- اعتماد أسماء المراحل والصفوف والمواد والمنهج التفصيلي والجهة التعليمية.
- أسعار الاشتراك، العملة، الباقات، التجديد، الإلغاء والاسترداد، واختيار بوابة الدفع.
- عدد الطلاب المتزامنين، عدد الحصص المتزامنة ومتوسط مدتها ونمو الاستخدام بعد سنة.
- تفسير «30 دقيقة» وتحديد زمن استجابة تقني وتوافر وRPO/RTO بمقاييس منفصلة.
- مزود البث والتخزين والجودة والحدود والتكلفة وسياسة التسجيل.
- تفسير 500 ميجابايت (متوسط أم حد أقصى)، جودات الفيديو والتنزيل والاستئناف عند الانقطاع.
- صلاحيات الأستاذ ومدير النظام ومراجع المحتوى وآلية المراجعة والنشر.
- سياسة حقوق المحتوى وترخيص الكتب والملفات والتسجيلات.
- مدد الاحتفاظ بالرسائل والتسجيلات والبيانات والنسخ، والتشفير واختبارات الاستعادة.
- سياسة إدارة الحسابات وكلمات المرور والمصادقة متعددة العوامل وقفل محاولات الدخول.
- قواعد الاختبار: الوقت والمحاولات واستئناف الإجابة والتصحيح الآلي وعرض النتائج.
- سياسة خصوصية الطلاب والقُصّر وإجراءات الموافقة والحذف.

لا تخترع قيمًا لهذه البنود؛ سجل القرار في Issue/وثيقة، ثم حدّث المخطط والتطبيق والوثائق عند اعتماده.

## 11. تقسيم العمل بين الفريقين

- **فريق الخلفية:** `app/`, `database/`, مصادقة PHP، PDO، الترحيلات، الصلاحيات، التكاملات والتشغيل.
- **فريق الواجهة:** `app/Views/`, `public/assets/`, تجربة RTL والتجاوب وسهولة الاستخدام.
- **مشترك:** عقد البيانات والـ API إن أضيف، تعديل مخطط يؤثر على صفحات، وحقوق الوصول وحالات الخطأ.

قبل مهمة مشتركة، اتفقوا على الحقول والمدخلات والمخرجات وحالات الخطأ والصلاحيات. لا تدفعوا مباشرة إلى الفرع الافتراضي؛ استخدموا فرعًا وPull Request وراجعوا تغييرات الترحيلات بعناية.

## 12. توجيهات للمساعد البرمجي

1. حافظ على PHP 8.4+ وPostgreSQL وPDO ما لم يصدر قرار جديد صريح.
2. اقرأ الترحيلات والشيفرة الفعلية قبل تعديلها، وميّز المتطلب عن التنفيذ.
3. لا تعدل ترحيلًا سبق تطبيقه؛ أنشئ ترحيلًا جديدًا.
4. استخدم استعلامات PDO المحضرة ومعاملات مناسبة، واختبر حالات الصلاحية السلبية والإيجابية.
5. لا تخترع أسعارًا أو عملات أو بيانات مناهج أو موفري خدمات أو مدد احتفاظ.
6. لا تعرض ملفات أو تسجيلات خاصة برابط عام. تحقق من صلاحية المستخدم والاشتراك على الخادم.
7. حافظ على دعم العربية RTL والاتصال المحدود.
8. حدّث جميع ملفات Markdown عند تغير التقنية أو الحالة أو القرارات. لا تصف ميزة مخططة بأنها منفذة.
