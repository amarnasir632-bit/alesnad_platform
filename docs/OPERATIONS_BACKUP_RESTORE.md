# تشغيل النسخ الاحتياطي والاستعادة

## النسخ الاحتياطي

تتطلب الأوامر PHP مع `pdo_pgsql` وأداتي PostgreSQL `pg_dump` و`pg_restore`، وقاعدة مطبّق عليها الترحيلات. اضبط اتصال `.env` قبل التشغيل:

```bash
php database/backup.php
```

ينشئ الأمر أرشيف PostgreSQL بصيغة custom داخل `storage/backups/` بصلاحيات مقيدة، ويسجل مفتاحه وحجمه وSHA-256 وحالته في `backup_records`. لا تُرفع ملفات النسخ إلى Git. تكرار النسخ والاحتفاظ والتشفير وموقع النسخة الخارجية قرارات تشغيل معلقة (OD-24)؛ اعتمدها الجهة قبل الإنتاج.

## الاستعادة

الاستعادة تستبدل المخطط والبيانات الموجودة في قاعدة الهدف. لا تشغّلها على قاعدة مستخدمة قبل اعتماد نافذة صيانة والتحقق من اسم الهدف. لا يقبل السكربت إلا نسخة مسجلة بحالة `VERIFIED` وبصمة مطابقة، ويتطلب تأكيد اسم قاعدة الهدف حرفيًا:

```bash
php database/restore.php --backup=db-<timestamp>-<random>.dump --confirm-target=alesnad_platform
```

استبدل مفتاح النسخة بالقيمة التي طبعها أمر النسخ، واسم قاعدة الهدف بالقيمة المحددة في `RESTORE_TARGET_DATABASE` أو `DB_DATABASE` إن لم تحدد الأولى. يبحث السكربت عن سجل النسخة في قاعدة المصدر `DB_DATABASE`، ثم يستعيدها إلى الهدف المؤكد. لا يطبع السكربت بيانات الاتصال أو تفاصيل استثناءات قاعدة البيانات. يستخدم `pg_restore --single-transaction` حتى يؤدي فشل الاستعادة إلى التراجع عن تغييرات الاستعادة.

## تجربة استعادة معزولة

نفّذ التجربة بعد أخذ نسخة ناجحة، وعلى قاعدة مؤقتة فارغة لا تحتوي بيانات مستخدمين. يلزم أن يملك مستخدم PostgreSQL صلاحية إنشاء قاعدة مؤقتة:

```bash
createdb alesnad_restore_drill
RESTORE_TARGET_DATABASE=alesnad_restore_drill php database/restore.php --backup=db-<timestamp>-<random>.dump --confirm-target=alesnad_restore_drill
DB_DATABASE=alesnad_restore_drill psql -c 'SELECT COUNT(*) FROM schema_migrations;'
DB_DATABASE=alesnad_restore_drill psql -c "SELECT status, checksum_sha256 FROM backup_records WHERE storage_key = 'db-<timestamp>-<random>.dump';"
dropdb alesnad_restore_drill
```

استبدل `<timestamp>-<random>` بمفتاح النسخة نفسه في جميع الأوامر. اعتبر التجربة ناجحة فقط إذا أعاد الاستعادة رمز نجاح، واحتوت القاعدة المؤقتة سجلات الترحيلات المتوقعة، وظهرت النسخة المستعادة بحالة `RESTORED` وبصمة مطابقة. احذف القاعدة المؤقتة بعد التحقق. سجّل تاريخ التجربة والنسخة وإصدار PostgreSQL والنتيجة في سجل تشغيل الجهة؛ لا تعتبر وجود هذا الإجراء دليلًا على أن تجربة فعلية نُفذت.

## فحوصات الصحة والسجلات

- `GET /health` نقطة عامة لفحص اتصال قاعدة البيانات. تعيد `200 {"status":"ok"}` أو `503 {"status":"unavailable"}` دون كشف عنوان القاعدة أو بيانات الاعتماد أو تفاصيل الاستثناء.
- يسجل التطبيق اسم الحدث ونوع الاستثناء ورمزه فقط. تُعرض رسالة عامة للعميل، ولا تُكتب رسالة الاستثناء أو SQL أو قيم الطلبات إلى السجل.
- اجمع سجلات PHP وخادم الويب في مكان محمي، وقيّد صلاحيات قراءتها وفق إعدادات الخادم.

## الترحيلات وبصمات الملفات

يقفل `database/migrate.php` تشغيل الترحيلات باستخدام PostgreSQL session advisory lock. يحفظ SHA-256 لكل ملف عند تطبيقه، ويوقف التشغيل إذا تغير ملف سبق تسجيل بصمته. سجلات `schema_migrations` القديمة التي لا تملك بصمة تُسجل لها بصمة المصدر الموجودة عند أول تشغيل لهذا الإصدار؛ لا يمكن استنتاج تاريخ تعديلها السابق من قاعدة البيانات، لذلك راجع سجل Git قبل اعتماد هذه الترقية على بيئة مشتركة.

اختبر استعادة النسخة على قاعدة مؤقتة قبل تشغيل الترحيلات. النسخ الأقدم من مخطط حالي قد تحتاج إلى تحديثات إضافية بعد الاستعادة؛ طبّق `php database/migrate.php` فقط بعد التحقق من النسخة وخطة التحديث.
