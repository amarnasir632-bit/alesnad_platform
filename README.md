# منصة الإسناد الأكاديمي

منصة تعليمية عربية تطورها وتشرف عليها شركة **AL WARITH**. تعرض الواجهة العربية من اليمين إلى اليسار، وتستهدف المنهج السوداني.

تشرح [وثيقة سياق المشروع](docs/PROJECT_CONTEXT.md) المتطلبات والأدوار وحالة التنفيذ. يشرح [دليل المساهمة](CONTRIBUTING.md) تقسيم العمل بين فريقي الواجهة والخلفية. وتوضح [خطة النشر](docs/DEPLOYMENT.md) المعمارية وموانع الإطلاق، بينما يشرح [دليل التجربة المجانية على Render وNeon](docs/FREE_HOSTING_RENDER_NEON.md) خطوات العرض قبل شراء الخادم.

## التقنية

| الطبقة | التقنية | الاستخدام |
| --- | --- | --- |
| Frontend | HTML5 وCSS3 وJavaScript ES6+ | صفحات متجاوبة ودعم RTL |
| Backend | PHP 8.4+ | منطق الخادم والجلسات والتحقق والصلاحيات |
| Database | PostgreSQL | تخزين البيانات العلائقية |
| الاتصال | PDO مع `pdo_pgsql` | استعلامات محضرة واتصال PostgreSQL |
| كلمات المرور | `password_hash` و`password_verify` | تجزئة والتحقق من كلمات المرور |
| تبادل البيانات | JSON عند إضافة API | الطلبات والاستجابات البرمجية |

يستخدم التطبيق PHP دون إطار عمل حاليًا. يعتمد على HTML وCSS وJavaScript للواجهة وPHP/PDO للخادم. يشرح `database/migrations/` مخطط قاعدة البيانات القابل للتطبيق. لا تحفظ أي نسخة من قاعدة البيانات أو أسرار الاتصال في Git.

## المتطلبات

- PHP 8.4 أو أحدث.
- إضافتا PHP `pdo_pgsql` و`PDO`.
- PostgreSQL، وعميل `psql` لإعداد مستخدم وقاعدة محليين.
- Git.

## إعداد قاعدة البيانات والتشغيل محليًا

أنشئ مستخدم وقاعدة فارغين في PostgreSQL. من طرفية Fedora مثلًا:

```bash
sudo -u postgres psql
```

ثم داخل `psql`:

```sql
DO $$
BEGIN
  IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'alesnad_app') THEN
    CREATE ROLE alesnad_app LOGIN;
  ELSE
    ALTER ROLE alesnad_app LOGIN;
  END IF;
END $$;
```

نفّذ الأمر التالي وحده، ولا تلصق معه أوامر أخرى؛ فهو يطلب كلمة المرور تفاعليًا:

```text
\password alesnad_app
```

أدخل كلمة مرور جديدة مرتين. بعد رجوع المؤشر `postgres=#`، أنشئ القاعدة إن لم تكن موجودة، ثم اعرض مسار ملف إعداد الاتصال:

```sql
SELECT format('CREATE DATABASE %I OWNER %I', 'alesnad_platform', 'alesnad_app')
WHERE NOT EXISTS (SELECT FROM pg_database WHERE datname = 'alesnad_platform') \gexec
ALTER DATABASE alesnad_platform OWNER TO alesnad_app;
SHOW hba_file;
\q
```

إذا ظهرت رسالة `\password: extra argument` بعد لصق عدة أسطر، نفّذ `\r` عند المؤشر `postgres=#` لمسح الأمر المعلّق، ثم أعد `\password alesnad_app` وحده وانتظر رجوع المؤشر قبل إدخال الأمر التالي.

احتفظ بمسار `pg_hba.conf` الذي يظهر من `SHOW hba_file;`. افتح الملف بهذا المسار:

```bash
sudoedit /المسار/الذي/ظهر/لك/من/SHOW-hba_file
```

أضف قاعدة الاتصال التالية **قبل أي قاعدة عامة قد تطابق الاتصال** مثل `host all all 127.0.0.1/32 ident`:

```text
host    alesnad_platform    alesnad_app    127.0.0.1/32    scram-sha-256
```

أعد تحميل الإعداد من طرفية أخرى:

```bash
sudo -u postgres psql -c 'SELECT pg_reload_conf();'
pg_isready -h 127.0.0.1 -p 5432
```

يجب أن يظهر `accepting connections`. إذا ظهر `no response`، فتحقق أن خدمة PostgreSQL تعمل قبل متابعة إعداد الموقع.

للتأكد أن قاعدة المصادقة الجديدة قُرئت وتسبق أي قاعدة عامة، نفّذ داخل `psql`:

```sql
SELECT line_number, database, user_name, auth_method, error
FROM pg_hba_file_rules
WHERE host(address) = '127.0.0.1'
ORDER BY line_number;
```

يجب أن يظهر صف `alesnad_platform` و`alesnad_app` و`scram-sha-256` قبل أي صف عام يستخدم `ident`، وأن تكون خانة `error` فارغة.

أنشئ ملف الإعداد المحلي إن لم يكن موجودًا، واكتب كلمة مرور `alesnad_app` التي اخترتها في `DB_PASSWORD`:

```bash
test -f .env || cp .env.example .env
```

عدّل `DB_PASSWORD` في `.env`. قبل التشغيل، عيّن قيم مهلة الجلسة وحدود محاولة الدخول التي يعتمدها مسؤول البيئة، وأنشئ سرًا بـ`openssl rand -hex 32` وضعه في `AUTH_THROTTLE_KEY`. تظل هذه القيم فارغة في المثال لعدم اعتمادها بعد، والتطبيق يتطلبها:

```text
SESSION_IDLE_TIMEOUT_SECONDS=
LOGIN_MAX_ATTEMPTS=
LOGIN_WINDOW_SECONDS=
LOGIN_LOCKOUT_SECONDS=
AUTH_THROTTLE_KEY=
```

ثم طبّق ترحيلات المخطط:

```bash
php database/migrate.php
```

قبل تشغيل الاختبارات، عيّن `QUIZ_MAX_ATTEMPTS`, و`QUIZ_INCOMPLETE_ATTEMPT_POLICY`, و`QUIZ_RESULT_VISIBILITY` في `.env`. عيّن أيضًا `QUIZ_DURATION_MINUTES` إذا لم يحدد الأستاذ مدة لكل اختبار. القيم تبقى فارغة في `.env.example` إلى أن يعتمد مالك المنصة السياسات؛ الخيارات المدعومة موضحة في `docs/API_CONTRACT.md`.

أنشئ حساب مدير النظام الأول من طرفية تفاعلية. لا يوجد حساب افتراضي أو كلمة مرور ثابتة:

```bash
php database/create_admin.php
```

شغّل خادم PHP المحلي:

```bash
php -S 127.0.0.1:8000 -t public public/router.php
```

افتح `http://127.0.0.1:8000`. لكل مطور قاعدة محلية مستقلة؛ يطبق الجميع ملفات الترحيل نفسها. لا ترفع `.env` أو النسخ الاحتياطية أو ملفات المحتوى الخاصة. تُحفظ ملفات المستخدمين خارج مجلد `public/`.

تحقق من الاتصال بقاعدة البيانات عبر `GET /health`. لإنشاء نسخة خاصة مسجلة ببصمة، شغّل `php database/backup.php`؛ راجع [إجراءات النسخ والاستعادة](docs/OPERATIONS_BACKUP_RESTORE.md) قبل الاستعادة، لأنها تستبدل بيانات قاعدة الهدف وتتطلب تأكيد اسمها.

## قاعدة البيانات

يحتوي `database/migrations/001_initial_schema.sql` الجداول والعلاقات والقيود والفهارس الأساسية، ويزرع `002_seed_access_control.sql` أدوار المستخدمين وصلاحياتهم. ترحيل `003_seed_initial_academic_structure.sql` يضيف بيانات أولية مؤقتة، ثم يزيل `006_owner_managed_curriculum.sql` الصفوف غير المستخدمة لكي يبدأ الكتالوج فارغًا وفق قرار المالك بإدخال المراحل والصفوف والمواد يدويًا. يضيف `004_manual_content_access.sql` سجل منح/سحب الوصول اليدوي، و`005_staff_invitations.sql` دعوات الفريق، و`007_quiz_feedback.sql` ملاحظات تصحيح الإجابات المقالية. لا يضيف المشروع موادًا أو أسعارًا. يُسجّل مشغل الترحيلات الملفات المطبقة في جدول `schema_migrations` ولا يعيد تطبيقها.

تضيف ملفات الترحيل الجداول والصلاحيات والتدقيق للمصادقة والمنهج والوصول اليدوي ودورة مراجعة المحتوى والاختبارات والحصص والرسائل. يضيف `010_cloudflare_stream_recording_refs.sql` قيود منع تكرار مدخل البث والتسجيلات. تفاصيل الترحيلات في `database/migrations/` وعقد API في `docs/API_CONTRACT.md`.

قرار إطلاق المنصة هو منح صلاحية المحتوى يدويًا من المدير أو المراجع، دون اشتراكات أو بوابة دفع. تبقى جداول الاشتراك والدفع موجودة للتوسع المستقبلي ولا تمنح أهلية محتوى الإطلاق.

## الوظائف الموجودة في المستودع

هذه القائمة تصف مكونات التطبيق. التشغيل يعتمد على إعداد البيئة، ونتائج الاختبارات مسجلة بصورة منفصلة في `docs/TRACEABILITY.md`؛ لا تعني القائمة وحدها اجتياز CI أو جاهزية النشر.

- اتصال PDO بإعدادات `.env`.
- ترحيل مخطط PostgreSQL وبذور الأدوار والصلاحيات.
- واجهة عربية RTL لعرض المواد الدراسية المدخلة في القاعدة.
- صفحة مدير لإضافة المراحل والصفوف والمواد يدويًا وربط المواد بالصف، محمية بصلاحية الخادم ومسجلة في سجل التدقيق.
- صفحة للمدير ومراجع المحتوى لمنح/سحب أهلية وصول الطالب يدويًا، مع سجل تاريخي وتدقيق، وحماية عرض الدروس المنشورة بناءً على قرار الوصول.
- دعوات حسابات الفريق بروابط لمرة واحدة صالحة 48 ساعة؛ المدير ومراجع المحتوى ينشئان حسابات الأستاذ والمراجع والمدير، ويحدد الموظف كلمة مروره بنفسه.
- إسناد المواد للأساتذة من صفحة الفريق؛ يقتصر إنشاء السؤال على الأستاذ المسند إليه أو المدير.
- بنك الأسئلة والاختبارات: الأستاذ المسند إليه ينشئ الأسئلة ويقدمها للمراجعة؛ المدير أو المراجع يعتمد النشر. يمكن إنشاء اختبارات من الأسئلة المعتمدة. بدء محاولات الطالب يتطلب اعتماد سياسات المحاولة والنتيجة في إعدادات البيئة، ولا يبدأ إذا كانت غير مضبوطة.
- مكتبة أولية لرفع الكتب والامتحانات بصيغة PDF إلى تخزين خاص خارج `public/`، أو إضافة روابط HTTPS للموارد؛ يعتمد المدير أو المراجع المحتوى قبل ظهوره للطالب ذي صلاحية الوصول اليدوية. الملفات لا تقدم مباشرة من مسار عام.
- اختبارات إلكترونية من الأسئلة المعتمدة للمادة، مع حفظ الإجابات والتصحيح الآلي للأسئلة الموضوعية وتصحيح يدوي للمقال. لا توجد سياسة افتراضية للمحاولات أو النتائج؛ المسارات ترفض بدء المحاولة حتى يضبطها مسؤول البيئة.
- تسجيل ذاتي للطالب مع اختيار الصف النشط وتسجيله في ملفه الدراسي، ثم منح المحتوى يدويًا من المدير أو المراجع؛ وتسجيل الدخول والخروج مع تجزئة كلمة المرور وCSRF.
- `/api/v1/` للجلسة والمصادقة وإدارة الحسابات والهيكل الدراسي وإسناد الأساتذة والبحث بالمحتوى والاختبارات.
- رفع الموارد والامتحانات والأسئلة ومراجعتها ونشرها، وتنزيل الملفات الخاصة للطلاب ذوي المنحة اليدوية النشطة، مع استئناف Range.
- بدء الاختبارات وإرسال الإجابات وتصحيح الموضوعي آليًا والمقالي يدويًا، وإظهار النتائج بحسب إعداد البيئة.
- إدارة الحصص من صفحة الحصص وAPI: غرفة بث عربية متجاوبة للمعلم والطالب، بث من المتصفح مع تحكم الكاميرا والميكروفون ومشاركة الشاشة، Cloudflare Live Inputs، وروابط مشاهدة موقعة ومزامنة التسجيلات الجاهزة. قائمة حضور متزامنة وسبورة تشاركية ومحادثة داخل الغرفة غير متاحة بعد؛ طلب المداخلة يسجل موافقة المعلم فقط ولا يفتح قناة صوت للطالب. يلزم اختبار حساب Cloudflare فعلي. الرسائل المتاحة فردية، ويلزم إعداد `MESSAGING_RATE_LIMIT_COUNT` و`MESSAGING_RATE_LIMIT_WINDOW_SECONDS` قبل الإرسال.
- التقويم المدرسي من `?page=school_schedule`: المدير يضيف حصصًا أسبوعية أو بتاريخ مفرد، وفسحًا عامة أو لصف محدد، وإجازات عامة أو لصف محدد تُعرض تلقائيًا في الصفحة الرئيسية والإعلانات. يتحقق الخادم من إسناد الأستاذ ويمنع تداخل أوقات الصف أو الأستاذ؛ يلزم تطبيق ترحيل `016_school_schedule_and_holidays.sql`.
- بث Cloudflare Stream المباشر يتكامل مع رفع فيديوهات الموارد التعليمية مباشرة إلى Cloudflare بروابط رفع أحادية الاستخدام؛ لا يمر ملف الفيديو عبر خادم التطبيق، ويصدر التشغيل برابط signed بعد فحص أهلية الطالب واعتماد المحتوى. يلزم إعداد قيم Cloudflare في `.env` وتطبيق ترحيل `012_cloudflare_video_uploads.sql`.
- الخطط والاشتراكات يمكن إدارتها يدويًا من المدير، وتنتهي حالة الاشتراك آليًا عند انتهاء الفترة. لا توجد أسعار افتراضية ولا بوابة دفع. يمكن تشغيل معالجة الانتهاء يدويًا أو دوريًا عبر `php database/expire_subscriptions.php`.
- تصنف المحاولات المنتهية بلا تسليم عند تفاعل الطالب معها، ويمكن تشغيل `php database/process_expired_quiz_attempts.php` دوريًا كل دقيقة بواسطة cron على الخادم. لا توفر خطة Render المجانية جدولة دورية دائمة؛ راجع [دليل Render وNeon](docs/FREE_HOSTING_RENDER_NEON.md) للتجربة فقط.
- تشغيل قاعدة البيانات يشمل قفلًا وبصمة SHA-256 للترحيلات، ونسخًا احتياطية خاصة عبر `pg_dump`، واستعادةً تتحقق من البصمة، ونقطة فحص الصحة `/health`.

عقد النقاط في `docs/API_CONTRACT.md`، والقرارات التي لا تزال بلا قيمة في `docs/OPEN_DECISIONS.md`. مصفوفات التتبع واختبارات المراحل في `docs/TRACEABILITY_PHASE_*.md` و`tests/`. تكامل الاختبار لا يعمل إلا على قاعدة يبدأ اسمها بـ`alesnad_test_`.

## الاختبارات والتحقق

- شغّل `php tests/password_policy.php`, و`php tests/content_range_unit.php`, و`php tests/database_url_unit.php`, و`php tests/quiz_policy_unit.php`, و`php tests/session_availability_unit.php`, و`php tests/school_schedule_unit.php` لاختبارات الوحدة، ثم `for check in tests/static_phase{1..8}_checks.py; do python3 "$check"; done` للفحوصات الساكنة.
- اختبارات PostgreSQL التكاملية ترفض العمل ما لم يبدأ اسم `DB_DATABASE` بـ`alesnad_test_`. شغّل `php database/migrate.php` قبل `tests/phase1_integration.php` و`tests/phase2_academic_integration.php`.
- GitHub Actions في `.github/workflows/backend-ci.yml` يوفر PostgreSQL 16 وPHP 8.4، ويشغّل الترحيلات واختبارات DB وHTTP وصلاحيات endpoints والوصول المباشر للملفات وتجربة النسخ والاستعادة.
- `docs/TRACEABILITY.md` يربط كل FR/NFR بالمكوّن والاختبار والنتيجة المسجلة. عند كتابة هذا التغيير لم يعمل workflow بعد؛ لا يشمل اختبارًا فعليًا للأداء أو UAT أو تكامل مزودي البث/التخزين غير المختارين.

## هيكل المستودع

```text
app/                    اتصال PDO والمصادقة وعروض PHP
database/migrations/    مخطط PostgreSQL وبذور الوصول
public/                 نقطة الدخول وأصول الواجهة العامة
storage/private/        مساحة محلية للملفات الخاصة، خارج web root
storage/backups/        مساحة محلية للنسخ الاحتياطية، غير متتبعة
docs/                   BRD وSRS وسياق المشروع
SqlDigram/              مخطط ERD المصدر والنسخ المصدرة
```

لا تضع أسرارًا في الشيفرة أو GitHub. عند النشر، استخدم HTTPS، واجعل `SESSION_SECURE=1`، واضبط مستخدم قاعدة البيانات بأقل صلاحيات لازمة، وأمّن `storage/` والنسخ الاحتياطية.
